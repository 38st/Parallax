# Critical user journeys

This matrix describes the supported macOS release candidate. “Verified” means
the behavior has direct automated or packaging evidence in this working tree.

| Journey | Expected behavior | Failure behavior | Verification |
| --- | --- | --- | --- |
| First launch / empty library | App opens without requiring existing state and presents an actionable empty state. | Invalid/corrupt state is preserved and recovery is shown rather than silently replaced. | Verified by package startup-resource smoke, library missing/empty/corrupt tests, and presentation tests. |
| Add or relink an application | Only a healthy `.app` is accepted; stable storage identity survives a move. | Non-app, unhealthy, wrong-bundle, conflicting, removed, or changed candidates are rejected. | Verified by `ApplicationRelinkCoordinatorTests`, health, importer, and storage-identity suites. |
| Create, rename, duplicate, and remove a space | Each profile receives unique logical/storage identity and isolated managed paths. | Collision, active process, stale version, or filesystem failure causes no partial metadata/data mutation. | Verified by profile, completion-gate, storage-identity, transaction, and failure-boundary tests. |
| Edit and navigate away from a profile | Dirty draft and staged Keychain bookkeeping remain scene-local and restorable. | List Open and destructive/duplicate actions refuse to use persisted stale settings and direct the user to save or discard. | Verified by `testUnsavedEditingDraftIsRetainedAndBlocksStaleListLaunch` and `SpacePresentationTests`. |
| Save & Open | The exact committed profile snapshot is prepared and opened. | Failed or stale save never opens; parsing/secret/isolation diagnostics remain blocking. | Verified by editor workflow, edit-session, compiler, and launch-preparation tests. |
| Open two different isolated profiles | Each process receives distinct generated storage and activity identity. | A duplicate singleton process or shared canonical path is rejected. | Verified by compiler collision, storage identity, lifecycle, and activity registry suites. |
| Two Parallax processes open the same profile | Exactly one durable check-and-create succeeds. | The losing request fails before application open unless the exact expert risk override is supplied. | Verified by separate-registry atomic exclusion and durable receipt adversary tests. |
| Track a successful open | Activity remains active until the exact process terminates. | Post-open registration failure enters visible degraded tracking and retains the safety gate. | Verified by launch lifecycle degraded-tracking regression. |
| Quit an exact managed instance from Parallax | PID plus start identity and application identity are revalidated; exit is marked expected. | PID reuse, another app, or rejected quit affects no other instance. | Verified by instance-controller and lifecycle tests. |
| Managed app exits unexpectedly | Profile data remains isolated, history says “Ended Unexpectedly,” and Open Again targets the same stable profile. | Missing or ambiguous crash evidence produces manual recovery only. | Verified by lifecycle, history presentation, and reopen logic tests. |
| Managed app produces a matching `.ips` crash report | PID/start or unique PID+bundle+time evidence links the report to the exact launch. | Bundle mismatch, time mismatch, PID ambiguity, or multiple fallback matches remain unlinked. | Verified by `ApplicationCrashReportLocatorTests`. |
| Automatic crash recovery | With setting enabled, only confirmed crashes retry after 2s then 8s; third crash in ten minutes opens the durable profile-scoped circuit across Parallax restarts/processes. | Intentional Parallax quit never retries; unconfirmed quit never retries; another profile has an independent budget; corrupt ledger evidence pauses automatic recovery. | Verified by lifecycle disposition, locator tests, and `ManagedAppRecoveryPolicyTests`. |
| Record the July 2026 PiP workaround | After externally applying it, the operator records verified state for the exact profile. The record survives restart. | Corrupt record bytes are quarantined; removing a record does not mutate third-party settings. | Verified by `ManagedAppWorkaroundStoreTests` and App Settings UI. |
| Store a launch secret | Keychain-backed environment references remain opaque in the library and resolve only during preparation. | Suspected secret-bearing argv is redacted and cannot be launched or exported unsafely. | Verified by security presentation, compiler, secret store, imported review, and portable export tests. |
| Import/export configuration | Supported schemas round-trip with explicit sensitive-data disclosure and conflict resolution. | Malformed, oversized, unsafe, stale, or unresolved imports fail without replacing the library. | Verified by import validator/conflict/replacement and portable configuration suites. |
| Relocate managed storage | Immutable plan previews exact moves; data publishes before one metadata commit; old data is cleaned only after success. | Capacity, activity, collision, cancellation, crash, or stale source recovers deterministically. | Verified by storage relocation and store integration suites. |
| Remove/archive application data | Exact stable targets are confirmed; archive/delete and metadata commit follow the documented transaction order. | Any boundary failure rolls back or resumes idempotently without following links or deleting external data. | Verified by application removal request/coordinator and secure filesystem suites. |
| Migrate or recover a library | Supported legacy fixtures migrate deterministically with verified backup and compare-and-swap publication. | Blockers, unsupported future schema, corruption, ambiguous replacement, and crash boundaries preserve evidence and fail closed. | Verified by migration, repository, backup, and recovery-hardening suites. |
| Package a candidate | App resources, architecture, signature, ZIP, DMG, hashes, and collision policy are independently verified. | Missing inputs, credentials, dirty release tree, or invalid artifact fails before publication. | Verified by packaging integration 5/5 and contract suite 4/4. |
| Installation lifecycle | Candidate clean install, prior-to-candidate upgrade, and byte-identical prior-version rollback execute in an isolated Applications directory with a fresh home and packaged-resource launch smoke at each stage. | Any copy, signature, version, launch, or rollback-integrity failure stops the rehearsal. | Verified automatically by packaging integration using `rehearse_install_upgrade_rollback.sh`; final signed clean-account rehearsal remains credential-gated. |
| Public signed release | Clean reviewed commit is signed, notarized, stapled, installed, upgraded, and rollback-tested. | Any gate failure is NO-GO. | Locally actionable unsigned rehearsal is verified; final execution is blocked by maintainer commit authority and Apple credentials. |

## Scope note

The `ParallaxMobile/` prototype is not a supported journey in this macOS
release. Its simulator build/tests are informational and do not satisfy a
mobile production-readiness gate.
